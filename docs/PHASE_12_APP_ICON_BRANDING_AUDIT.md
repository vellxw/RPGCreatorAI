# Phase 12 App Icon And Branding Asset Audit

Issue: PX-011 / FRA-445
Date: 2026-06-08
Milestone: M01 - Launcher, Desktop Entry, Splash, And Startup UX

## Result

The desktop icon baseline is present and usable for M01 launcher work. The
project has a committed SVG source, generated Tauri desktop icon outputs,
Windows square logo outputs, coherent product metadata, and a focused branding
verification script.

No new branding asset generation is required for PX-011. The follow-up work is
to reuse the existing icon baseline in launcher, splash, shortcut, and packaged
desktop-entry validation paths, then capture new M01 evidence after those
surfaces exist.

## Gaps For M01 Implementation

1. Splash branding surface is not defined yet.
   - There is no dedicated splash image, splash layout token, or startup
     progress treatment beyond the app icon source. M01 splash work should
     reuse the app icon unless a later issue explicitly approves a new visual
     asset.
2. Launcher/shortcut evidence is still Phase 11-level.
   - `docs/screenshots/phase11-branding/packaged-exe-icon.png` proves the
     packaged executable associated icon was captured earlier. M01 should add
     fresh evidence for the actual desktop entry, Start Menu entry, or
     shortcut behavior when that package/installer flow is in scope.
3. Human-facing display name must stay `RPGCreatorAI`.
   - Technical slugs are intentionally different: `rpgcreator-ai-editor` for
     npm and `rpgcreator-shell` for Rust/Tauri output. Launcher and shortcut
     UI should display `RPGCreatorAI`, not the technical shell/package names.
4. README does not present the app icon or logo near the top.
   - This is acceptable for the current repo README, which leads with product
     description and editor screenshots. If M01 adds a launcher-facing product
     page or first-run screen, it should use the existing icon source rather
     than introduce a separate logo without a scoped issue.
5. No signed installer or publisher identity is available.
   - This is not a PX-011 gap to fix. Signing, store upload, publisher identity,
     and release credentials remain outside repo-local autonomous work.

## M01 Follow-Up Checklist

- Use `src-tauri/icons/icon-source.svg` as the source of truth for launcher and
  splash branding unless a later Linear issue explicitly changes branding.
- Keep `src-tauri/tauri.conf.json` `productName`, window title, and bundle
  descriptions aligned with `RPGCreatorAI`.
- Run `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/dev/verify-branding-assets.ps1`
  after any icon or Tauri branding metadata change.
- When a packaged desktop-entry or shortcut flow is changed, capture fresh
  evidence with the packaged executable/shortcut visible and record it in the
  relevant issue doc and `docs/VALIDATION_LOG.md`.
- Do not commit installer outputs, generated binaries, signing certificates,
  package target directories, or ad hoc exported icon files.

## Decision

PX-011 is green as a baseline audit. Existing branding assets are sufficient
for M01 implementation, and the required follow-up is validation/evidence on
launcher, splash, and shortcut surfaces rather than asset creation.
